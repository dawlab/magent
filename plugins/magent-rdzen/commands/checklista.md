# Checklista / audyt (`/checklista`)

Uruchamiasz jedną z trzech checklist z `moduly/checklisty.md` (skill `marketing`) na **realnym** materiale właściciela. Nie oddajesz promptu — przechodzisz po materiale i dajesz priorytety.

## 1. Wybierz checklistę
- `$ARGUMENTS` = `strona` / `publikacja` / `oferta` → bierz tę.
- Brak argumentu → zapytaj krótko, co oceniamy: stronę/wizytówkę, konkretną treść przed publikacją, czy ofertę/sekwencję email.

## 2. Zbierz wejście
- **strona**: poproś o URL (albo o którą wizytówkę Google chodzi). Pobierz treść strony (WebFetch/odczyt). Sprawdź w `system/obszary-zainstalowane.md`, czy podłączony Clarity/Search Console — jeśli tak, oprzyj wnioski na realnych danych; jeśli nie, powiedz, że oceniasz z samej treści.
- **publikacja**: poproś o treść do sprawdzenia (albo weź ostatnią z `outputs/`).
- **oferta**: poproś o tekst strony oferty albo o sekwencję maili.

## 3. Przejdź checklistę i daj wynik
Zastosuj właściwą sekcję z `moduly/checklisty.md`. Zwróć **3–5 poprawek priorytetowo** (wpływ × łatwość), każda z konkretem „zmień X na Y". Nie recytuj całej listy kontrolnej — pokaż, co ruszyć najpierw i dlaczego.

## 4. Zapisz (jeśli warto)
Dłuższy audyt strony/oferty zapisz do `outputs/audyt/[data]-[co].md` + wpis w INDEX, żeby dało się wrócić i zmierzyć poprawę. Krótki pre-flight nie wymaga zapisu.

## Granice
Oceniasz i rekomendujesz — **nic nie publikujesz, nie wysyłasz, nie wdrażasz**. Materiał do ludzi → po ton do `glos`. Zero zmyślania: brak narzędzia/danych → nazwij, nie zgaduj.
